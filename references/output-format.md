# 杀手数独解题输出规范

## 一、表达规范（硬性）

全部用中文记号，不用 Box/RxCy：

- 宫 → **第X宫**（左上为第1宫，按行排到右下第9宫）
- 行列 → **第X行 / 第X列**；具体格子 → **X行X列**（如 7行9列）
- 笼子 → **和为X的N格笼子**（如"和为24的3格笼子"），不用"笼1/笼2"编号；遇到同和值笼子，附格子位置区分（如"和为14的3格笼子(首格6行8列)"）

## 二、交付格式：照抄版（最终交付必须用这个）

用户要解题过程时，最终交付按动笔顺序列出，每步只含两样东西：

1. **在哪写几**（如"2行5列写2"）
2. **一句话大白话原因**（如"第2行九格加起来45，行里和17、和26俩笼子占了43，剩那格就是2"）

规则：

- 连锁推出来的数字**不解释**，直接按顺序列"格子=数字"，标注"连锁，填一个挤一个"
- 开局铅笔标记（唯一组合数对）单独列一小节："哪两格圈什么对"
- 禁止在交付正文里出现术语：幽灵笼子、反证法、线性消元、隐性唯一——原因用大白话转述（如"反证法"→"当它是X试试，往下推必撞墙"）
- 详细编号步骤单只作底稿备查，不作为交付正文

## 三、协作模式

- **"今日题，手把手"**：逐步带解，一步一格，每步因果给全（看哪/因为啥/压掉啥/锁了啥）；用户说"过"才走下一步；卡住就把那步掰细
- **"今日题，照老规矩"**：直接跑完整流程，交付照抄版
- 用户贴进度验证推理：只判对错，不往下续推
- 用户明确说"可以给答案了"才给解盘

## 四、标准流程（拿到新题）

1. **核对数据**：81格、笼子总和=405、笼子格子不重叠
2. **后台跑脚本**（从技能目录）：
   - `python scripts/killer45_scan.py <题目.json>` → 45法则全量报告 + `_45map.html` 盘面高亮图
   - `python scripts/human_solve.py <题目.json>` → 编号步骤单 `<题目名>_steps.txt`
   - `python scripts/replay_check.py <题目.json> <步骤单.txt>` → 步骤单验真（必须 0 错误才可交付）
3. **按输出规范整理照抄版交付**

## 五、唯一组合速查（2~4格）

| 格数 | 唯一组合的和值 |
|---|---|
| 2格 | 3={1,2}、4={1,3}、16={7,9}、17={8,9} |
| 3格 | 6={1,2,3}、7={1,2,4}、23={6,8,9}、24={7,8,9} |
| 4格 | 10={1,2,3,4}、11={1,2,3,5}、29={5,7,8,9}、30={6,7,8,9} |

## 六、45法则

通用公式：**某区域外格之和 = 与该区域相交的所有笼子之和 − 45**（两宫=90、三宫=135、行+宫=90−重叠3格）。

三坑：没全在区域内的笼子不能计入；剩余多格时得到的是"和"不是单个数字；跨区笼的重叠格别数重。
